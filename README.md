# شركة النصر للعمليات — Next.js

نسخة **React / Next.js (App Router + TypeScript)** من لوحة العمليات وصفحة الدخول، بنفس الهوية البصرية، لكن ببنية جاهزة للربط بـ API حقيقي: طبقة `lib/api.ts`، مسارات API داخلية، حماية بالجلسات، ومكوّنات قابلة لإعادة الاستخدام.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:3000  (تطوير)
# أو للإنتاج:
npm run build && npm start
```

بيانات الدخول التجريبية: `admin@alnasr.com` / `1234` — وكلمة المرور `0000` تُظهر حالة الخطأ.

> **وضع المعاينة**: `.env.local` يفعّل `DEMO_MODE=1` ليعمل التصفّح داخل الإطارات المضمّنة حيث تُحجب الكوكيز.
> في الإنتاج احذف هذا السطر (أو اجعله `0`) ليعود الحماية الكاملة عبر الجلسة.

## واجهات الـ API

| المسار | الطريقة | الوصف |
|---|---|---|
| `/api/auth/login` | POST | `{email, password}` → يضبط `amanah_session` (HttpOnly) |
| `/api/auth/logout` | POST | ينهي الجلسة |
| `/api/operations` | GET | `q, status=posted,review, type, method, dir, from, to, sort=id\|date\|amount, order, page, perPage` → `{rows,total,allTotal,page,pages,statusCounts,kpis}` |
| `/api/operations/:id` | GET / PATCH | `PATCH {status}` لاعتماد/تغيير الحالة |
| `/api/summary` | GET | `?days=14` → `{kpis,statusCounts,series,recent}` |
| `/api/webhooks/whatsapp` | GET / POST | تحقّق ميتا + استقبال الرسائل وأوامر «اعتماد/رفض» |
| `/api/webhooks/wakeed` | POST | تحديث حالة الفاتورة من وكيد |
| `/api/integrations/whatsapp/test` | POST | `{to,text}` رسالة اختبار (أو محاكاة بلا مفاتيح) |
| `/api/integrations/wakeed/sync` | POST | `{id}` دفع عملية إلى وكيد |
| `/api/integrations/status` | GET | حالة التكاملات + سجل الأحداث |
| `/api/integrations/whatsapp/web/*` | POST/GET | ربط جهاز واتساب بـ QR + إرسال + فصل |

## كيف تربطه ببياناتك الحقيقية

1. **استبدال Mock بقاعدة بيانات**: افتح `lib/mock.ts` واستبدل الدوال (`allOperations`, `getOperation`, `updateStatus`) باستعلامات Prisma/Drizzle أو أي ORM — أبقِ نفس التوقيعات ولن يتغيّر أي مكوّن.
2. **خادم خارجي**: ضع `NEXT_PUBLIC_API_BASE=https://api.example.com` في `.env.local`، وعدّل مسارات CORS/التحقق. (أو استخدم `rewrites` في `next.config.mjs`).
3. **الصلاحيات**: `middleware.ts` يتحقّق حاليًا من وجود الكوكي؛ في الإنتاج تحقّق من توقيع JWT أو استعلم الجلسة، وأضف تحققًا من الدور داخل `route.ts` قبل السماح بـ `PATCH`.
4. **الترحيل الفعلي**: منطق «اعتماد وترحيل» في `app/api/operations/[id]/route.ts` هو المكان لكتابة القيد المحاسبي والتحقق وسجل التتبّع.

## ما هو مُنفَّذ فعليًا

- **دخول حقيقي**: تحقّق من الحقول، حالة تحميل، رسائل خطأ من الخادم، حماية مسارات، وخروج.
- **جدول العمليات**: الفلترة والترتيب والترقيم **على الخادم** (query params)، بحث من الشريط العلوي عبر `?q=` مشترك بين الصفحات.
- **الاعتماد والترحيل** يعدّل الحالة عبر `PATCH` ثم يعيد التحميل، والعدادات والرسوم تتحدّث معه.
- **تصدير CSV** مبني من نفس الفلاتر (UTF‑8 + BOM) وتحديد جماعي.
- **رسوم بيانية** SVG خالصة (بلا مكتبات): منطقة تفاعلية + دونات + Sparkline.
- **وضع ليلي** بلا وميض (سكربت قبل الرسم) ومحفوظ في `localStorage`.
- **متجاوب** حتى 360px، وواجهة عربية RTL بالكامل.


## التكاملات: واتساب و«وكيد»

صفحة **الإعدادات والتكاملات** (`/settings`) تعرض حالة الربط، عناوين الويبهوك، اختبار الإرسال، وسجل الأحداث.

### 1) واتساب — WhatsApp Cloud API (ميتا، رسمي)

الملفات: `lib/integrations/whatsapp.ts` · `app/api/webhooks/whatsapp/route.ts` · `app/api/integrations/whatsapp/test/route.ts`

الخطوات:
1. حساب **Meta for Developers** ← تطبيق من نوع Business ← إضافة منتج **WhatsApp**.
2. من WhatsApp → API Setup خُذ **Phone number ID** وأنشئ **System User token** دائمًا (صلاحية `whatsapp_business_messaging`).
3. ضع في `.env.local`: `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`, `WHATSAPP_VERIFY_TOKEN` (نص تختاره), `WHATSAPP_APP_SECRET`, و`WHATSAPP_NOTIFY_TO` (اختياري).
4. في **Configuration → Webhook** ضع `https://<نطاقك>/api/webhooks/whatsapp` ونفس قيمة `VERIFY_TOKEN`، ثم اشترك في الحقل **messages**.
5. للرسائل التي تبدأها أنت (خارج نافذة 24 ساعة) أنشئ **قالبًا معتمدًا** باسم `amanah_operation_posted` بثلاثة متغيّرات: اسم العميل، رقم العملية، المبلغ.

ما يفعله الكود:
- `GET /api/webhooks/whatsapp` يردّ على تحقّق ميتا (`hub.challenge`).
- `POST` يتحقّق من توقيع `X-Hub-Signature-256` (HMAC بـ App Secret، مقارنة آمنة زمنيًا) ثم يعالج الرسالة.
- أوامر جاهزة: **«اعتماد OP-24599»** / **«رفض OP-24599»** تغيّر حالة العملية فورًا وتردّ على المرسل.
- `notify.onOperationPosted` يرسل قالبًا عند الترحيل، وإن لم يكن القالب معتمدًا يسقط تلقائيًا إلى رسالة نصية.

### 2) «وكيد» — API + Webhook

الملفات: `lib/integrations/wakeed.ts` · `app/api/integrations/wakeed/sync/route.ts` · `app/api/webhooks/wakeed/route.ts`

وكيد **لا ينشر توثيقًا عامًا**؛ ميزة «API & Webhook» مذكورة في موقعه وتُفعَّل بالتواصل معهم. لذلك بُني التكامل كطبقة معزولة:
1. اطلب من وكيد: `Base URL`، `API Key`، مسارات الفواتير/القيود، و`Webhook Secret`.
2. ضعها في `.env.local` (`WAKEED_BASE_URL`, `WAKEED_API_KEY`, `WAKEED_WEBHOOK_SECRET`) — **بلا تعديل كود**.
3. إن اختلفت أسماء الحقول: عدّل فقط `mapOperationToWakeedInvoice()` وثابت `ENDPOINTS` في نفس الملف.
4. كل عملية تُرحَّل تُرسل كفاتورة (`pushOperationToWakeed`) أو كقيد يومية (`pushJournalEntry`)، مع `external_id = رقم العملية` لمنع التكرار.
5. ويبهوك وكيد يحدّث الحالة عكسيًا (فاتورة مدفوعة ⇒ ترحيل).

### 3) ربط جهاز واتساب (QR / الأجهزة المرتبطة) — بديل بلا API رسمي

الملفات: `lib/integrations/wa-web.ts` · `app/api/integrations/whatsapp/web/{connect,status,logout,send}/route.ts`

يعمل مثل «واتساب ويب»: تُمسح مرة واحدة من جوالك، فتصبح المنصّة ترسل من **رقمك نفسه** وتستقبل أوامر
«اعتماد OP-…» / «رفض OP-…» عبر مكتبة **Baileys** (بروتوكول الأجهزة المتعددة، بلا متصفح ولا Chromium).

**الاستخدام:** `/settings` ← بطاقة «ربط جهاز واتساب» ← **بدء الربط** ← امسح الرمز من:
واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز.

| المسار | الوظيفة |
|---|---|
| `POST /api/integrations/whatsapp/web/connect` | بدء الجلسة وإظهار QR |
| `GET /api/integrations/whatsapp/web/status` | الحالة + رمز QR (data URL) + الرقم المرتبط |
| `POST /api/integrations/whatsapp/web/send` | `{to,text}` إرسال من الرقم المرتبط |
| `POST /api/integrations/whatsapp/web/logout` | فصل الجهاز |

**تفاصيل تقنية**
- الجلسة تُخزَّن في `.wa-auth/` (مضاف إلى `.gitignore`) وتُستأنف تلقائيًا بعد إعادة تشغيل الخادم.
- رمز QR يُجدَّد تلقائيًا؛ الواجهة تستطلع الحالة كل 2.5 ثانية.
- إعادة اتصال تلقائية (حتى 5 محاولات) عند انقطاع الشبكة، وإيقاف عند `loggedOut`.
- يتطلب **خادم Node دائم** (ليس Serverless/Edge) ونسخة واحدة فقط لكل رقم (نسختان = تعارض جلسات).

**المخاطر والحدود (اقرأها قبل الاستخدام)**
- غير رسمي ويخالف شروط خدمة واتساب ⇒ احتمال **حظر الرقم**. الأنسب لرقم داخلي/تشغيلي.
- لا يوفّر ضمانات تسليم مثل Cloud API، وقد تتغيّر البروتوكولات في أي وقت.
- من يملك مجلد `.wa-auth` يستطيع التصرّف بالحساب — احمِه واحذفه عند التوقف.
- للإشعارات الرسمية للعملاء (فواتير/ترحيب) استخدم **Cloud API** — ويمكن تشغيل الاثنين معًا:
  الجهاز المرتبط لأوامر الفريق، وCloud API لرسائل العملاء.

**بديل جاهز (Docker)**: إن أردت خدمة REST منفصلة بدل الكود المدمج، جرّب **WAHA** أو **Evolution API** —
تتصل بها من `lib/integrations/whatsapp.ts` بنفس أسلوب الطلب، ويبقى الربط معزولًا عن التطبيق.

### نقاط الإنتاج (مهمة)
- **طابور**: لا تُرسل الرسائل/الفواتير داخل الطلب مباشرة؛ استخدم BullMQ/Redis أو SQS مع إعادة محاولة وتأخير تصاعدي.
- **منع التكرار**: `external_id` + تخزين نتيجة كل محاولة (جدول `IntegrationEvent` بدل السجل في الذاكرة).
- **الأسرار**: مدير أسرار (Vault/SSM) لا ملفات في المستودع، وتدوير المفاتيح دوريًا.
- **المراقبة**: تنبيه عند تجاوز نسبة فشل معيّنة، ولوحة صحة لكل تكامل.


## شيت الترحيل والتصدير إلى Excel

صفحة «شيت الترحيل» (`/sheet`) تجمع الحركات المُرحَّلة في شيت واحد بالأعمدة الإحدى عشرة نفسها:
الحساب · البيان · مدين · دائن · العملة · التعادل · المكافآت · مركز التكلفة · التاريخ · المبلغ · الحساب المقابل.

- الترحيل: من صفحة العمليات («ترحيل إلى الشيت» للحركات المحددة) أو `POST /api/sheet/post` مع `{"all":true}`.
  التكرار يُستبعد تلقائيًا حسب `opId`، ويمكن تحديد `costCenter` أثناء الترحيل.
- التعديل داخل الشيت: مركز التكلفة، الحساب المقابل، المكافآت، المدين/الدائن، البيان — عبر `PATCH /api/sheet/:id`، أو حذف السطر بـ `DELETE`.
- وضعان للتصدير:
  - `mode=single` (الافتراضي): سطر واحد لكل حركة بطرف مدين أو دائن + الحساب المقابل. هذا الوضع **غير متوازن بطبيعته**، ولذلك يتحقق من «سلامة السطور» لا من التساوي.
  - `mode=double`: قيد مزدوج — سطران لكل حركة (الطرف والحساب المقابل)، مجموع المدين = مجموع الدائن.
- التصدير: `GET /api/sheet/export?mode=single|double` → ملف `amanah-sheet-<التاريخ>-<mode>.xlsx` بترويسة عربية RTL،
  تجميد الصفوف، فلتر تلقائي، صف إجماليات (رمادي) وصف تحقق من التوازن (أخضر/أحمر)، وتلوين المدين/الدائن.

| الميثود | المسار | الوظيفة |
| --- | --- | --- |
| GET | `/api/sheet` | السطور + الإجماليات + الحركات غير المرحَّلة |
| POST | `/api/sheet/post` | ترحيل `{ids}` أو `{all:true}` مع `costCenter` اختياري |
| PATCH | `/api/sheet/:id` | تعديل سطر (مركز تكلفة/حساب مقابل/مكافآت/مدين/دائن/بيان) |
| DELETE | `/api/sheet/:id` | حذف سطر |
| GET | `/api/sheet/export?mode=` | تصدير Excel بوضع فردي أو مزدوج |

> ملاحظة: سطور الشيت محفوظة في ذاكرة السيرفر (`__amanahSheet`) لأغراض العرض، وتُفقد عند إعادة التشغيل —
> أعد الترحيل بعد كل `npm run start`. في الإنتاج انقلها إلى جدول `sheet_lines` مع فهرس فريد جزئي على `op_id`.

### ما أُضيف ليعمل دائمًا

- **تخزين دائم:** سطور الشيت تُحفظ في `${DATA_DIR}/sheet-lines.json` (كتابة ذرّية) فتبقى بعد إعادة التشغيل.
- **ترحيل تلقائي مجدول:** `AUTO_POST_INTERVAL_MIN` — يرحّل كل الحركات غير المدرجة، بلا تكرار، ويحفظ فورًا.
- **استئناف واتساب:** يُعاد ربط الجلسة المحفوظة في `WA_AUTH_DIR` تلقائيًا عند الإقلاع (`WA_AUTO_CONNECT=1`).
- **ملخّص واتساب:** `WA_AUTO_SUMMARY_TO` → رسالة بعد كل دورة فيها حركات جديدة.
- **فحص صحة:** `GET /api/health` (حالة التطبيق، الشيت، واتساب، آخر دورات الترحيل، التخزين).
- **جلسة موقّعة:** كوكي `amanah_session` بـ HMAC-SHA256، وتُتحقَّق في الـ middleware — لا يمكن تزويرها.
- **بيانات دخول من البيئة:** `ADMIN_EMAIL` + `ADMIN_PASSWORD` (+ `SESSION_SECRET`) تُفرض عند ضبطها.

## واتساب: الربط بالرمز + ترحيل الحركات الواردة إلى الشيت

### 1) الربط برمز الاقتران (بدل مسح QR)

`POST /api/integrations/whatsapp/web/connect` مع `{ "phone": "9639xxxxxxxx" }`
→ يعيد `pairingCode` (8 خانات، تُعرض `XXXX-XXXX`). تُدخله في:
واتساب ← الإعدادات ← الأجهزة المرتبطة ← ربط جهاز ← **«الربط برقم الهاتف بدلًا من ذلك»**.
بدون `phone` يعمل بالـ QR كما كان. الحالتان: `qr` و`pairing`، ثم `connected`.

### 2) كل رسالة واتساب فيها مبلغ = حركة في الشيت

عند وصول رسالة إلى الرقم المرتبط (محادثة مباشرة أو مجموعة):

1. يُستخرج منها: **المبلغ** (يدعم `1,250,000` و`500 ألف` و`2 مليون` والأرقام العربية)، **الاتجاه**
   (وارد/صادر)، **النوع** (تحويل/إيداع/سحب/دفع فاتورة/شحن رصيد/استرداد/تسوية)، **الوسيلة**
   (بنك/كاش/محفظة/بطاقة/شيك)، و**الجهة**.
2. تُنشأ حركة بحالة «مُرحّلة» وتُرحّل **فورًا** إلى الشيت (سطر جديد + مركز تكلفة افتراضي).
3. يردّ النظام على المرسل برقم الحركة والمبلغ وسطر الشيت.

أمثلة يعمل بها:
```
تحويل 500000 من شركة النور بنك
دفع فاتورة 150000 كهرباء كاش
إيداع 2,750,000 مخبز السنابل محفظة
سحب 30000 مصاريف صندوق
صادر 1200000 حوالة إلى مؤسسة الجبل بنك
```

### 3) إرسال الشيت إلى واتساب

- من صفحة `/sheet`: زر **«إرسال إلى واتساب»** (رسالة منسّقة فيها الحركات والمجاميع ومراكز التكلفة).
- من `/settings`: اختيار **مجموعة واتساب** من قائمة المجموعات المرتبطة أو إدخال رقم، ثم «إرسال الشيت».
- تلقائيًا بعد كل دورة ترحيل: `WA_AUTO_SUMMARY_TO` (رقم أو JID مجموعة).

| المسار | الوظيفة |
| --- | --- |
| `POST /api/integrations/whatsapp/web/connect` | بدء الربط: QR أو `{phone}` لرمز الاقتران |
| `GET /api/integrations/whatsapp/web/groups` | مجموعات واتساب المتاحة |
| `POST /api/integrations/whatsapp/web/send-sheet` | إرسال الشيت إلى رقم/مجموعة |
| `GET /api/integrations/whatsapp/inbox` | سجل الرسائل الواردة ونتيجة تحويلها |
| `POST /api/integrations/whatsapp/ingest` | تحويل نص إلى حركة (نفس المحرّك، للتجربة أو الإدخال من الواجهة) |

### مصادر الرسائل المقبولة

| المصدر | يُستقبل؟ | ملاحظة |
| --- | --- | --- |
| رسالة من رقم آخر إلى الرقم المرتبط | ✔ | يُرسل تأكيد للمرسل |
| رسالة إلى **مجموعة** | ✔ | `WA_INGEST_GROUPS=0` لتعطيلها |
| رسالة من الرقم المرتبط إلى **محادثة نفسك** | ✔ | أسهل طريقة للتجربة |
| رسالة صادرة من الرقم المرتبط إلى عميل/مجموعة | ✔ افتراضيًا | `WA_INGEST_FROM_ME=0` لتعطيلها — ولا يُرسل تأكيد للعميل في هذه الحالة |
| ردود النظام نفسها (✅/📊) | ✘ | مستبعدة لمنع التكرار |

> ملاحظة تقنية: بعض أحداث واتساب تصل بنوع `append` (لا `notify`) خصوصًا الرسائل الصادرة،
> ولذلك نقبل النوعين — وإلا فلن تُعالَج رسائل كثيرة.

### فحص الاستقبال ذاتيًا

`POST /api/integrations/whatsapp/web/selftest` — يرسل حركة تجريبية (`1,000`) من رقمك إلى **محادثة نفسك**،
ثم يخبرك إن وصلت ونتيجة معالجتها. نفس الزر موجود في صفحة الإعدادات: **«فحص الاستقبال الآن»**.
(يُضاف سطر بمقدار 1,000 إلى الشيت — احذفه بعد الفحص إن أردت.)

`GET /api/integrations/whatsapp/web/diagnostics` — آخر الرسائل التي وصلت للخادم ونتيجة كل واحدة
(حركة / غير مفهومة / صادرة تم تجاهلها)، لعرض «تشخيص الوصول» في الإعدادات.

### المتغيّرات

```env
WA_INGEST_ENABLED=1     # 0 = إيقاف استقبال الحركات من واتساب
WA_INGEST_GROUPS=1      # 0 = تجاهل رسائل المجموعات (المحادثات المباشرة فقط)
WA_INGEST_FROM_ME=1     # 0 = تجاهل الرسائل الصادرة من الحساب المرتبط
WA_AUTO_SUMMARY_TO=     # رقم أو JID مجموعة يصلها ملخّص كل ترحيل
```

> الحركات الواردة من واتساب تُحفظ في `DATA_DIR/wa-operations.json` والسجل في `DATA_DIR/wa-inbox.json`،
> فتظل بعد إعادة التشغيل. في الإنتاج انقلها إلى جدول `operations` مع فهرس على `wa_message_id` لمنع التكرار.

## شيت لكل محادثة/مجموعة واتساب

كل محادثة أو مجموعة تصل منها حركة يُنشأ لها **شيت مستقل تلقائيًا** باسمها، ويبقى الشيت الرئيسي
لأي حركة لا تنتمي لمحادثة (أوامر النظام/الإدخال اليدوي).

- **في الصفحة:** شريط شرائح أعلى `/sheet` — «كل الشيتات» + كل شيت وعدد سطوره.
  أزرار: **شيت جديد** · **إعادة تسمية** · **حذف الشيت** · **حذف الحركات**.
- **التصدير:** Excel لكل شيت على حدة (`/api/sheet/export?mode=single|double&sheet=<id>`)
  بعنوان واسم ورقة واسم ملف يحمل اسم الشيت (بصيغة عربية `filename*` + ASCII احتياطي).
- **إرسال واتساب:** يُرسل سطور الشيت المختار فقط.
- **أسماء الشيتات:** اسم المجموعة من واتساب، واسم المرسل في المحادثة المباشرة،
  و«محادثة نفسي» في محادثة الرقم مع نفسه. تُحدَّث تلقائيًا إذا تغيّر اسم المجموعة
  (إلا إذا أعدت التسمية يدويًا).

| المسار | الوظيفة |
| --- | --- |
| `GET /api/sheets` | كل الشيتات + عدد السطور ومجاميعها |
| `POST /api/sheets` | إنشاء شيت يدوي `{name}` |
| `PATCH /api/sheets/:id` | إعادة تسمية |
| `DELETE /api/sheets/:id` | حذف الشيت وكل سطوره |
| `GET /api/sheet?sheet=<id\|all>` | سطور الشيت + مجاميعه + قائمة الشيتات |
| `DELETE /api/sheet?sheet=<id\|all>` | حذف سطور شيت (أو كل الحركات) |
| `GET /api/sheet/export?mode=&sheet=` | تصدير شيت واحد أو الكل |

### بدء نظام فارغ (بلا بيانات تجريبية)

```env
DEMO_OPS=0     # لا حركات تجريبية — الحركات تأتي من واتساب فقط
```
مع `DEMO_OPS=0` تبدأ بلا أي حركة، والشيتات تُنشأ مع أول رسالة من كل محادثة/مجموعة.

## العملات + شيت لكل يوم + ملخّص نهاية اليوم

### 1) العملة تُكتشف من الرسالة
كل حركة تُسجَّل بعملتها الصحيحة بدل عملة واحدة ثابتة:

| في الرسالة | العملة المسجّلة |
| --- | --- |
| `1200 دولار` · `1200 USD` · `$1200` | `USD` |
| `2,750,000 جنيه` · `EGP` · `ج.م` | `EGP` |
| `ليرة` · `ل.س` · `SYP` | `SYP` |
| `ريال` · `درهم` · `دينار` · `يورو` · `TRY` | `SAR` · `AED` · `JOD` · `EUR` · `TRY` |
| بلا ذكر عملة | `DEFAULT_CURRENCY` (افتراضي `USD`) |

- المجاميع تُحسب **لكل عملة على حدة** (لا يصح جمع الدولار مع الجنيه).
- في Excel: عمود العملة لكل سطر، وصف إجمالي عام (يُفرَّغ عند تعدّد العملات)
  + **صف إجمالي لكل عملة**.
- في الواجهة: «مجموع مدين/دائن» يُظهر كل عملة في سطر مستقل عند التعدّد.

### 2) شيت لكل يوم (ولكل محادثة)
- معرّف الشيت صار `محادثة/مجموعة + اليوم`: مثال `group-120363…--2026-11-21`.
- صفحة `/sheet` فيها شريط **اليوم**: اليوم · أمس · أيام سابقة · كل الأيام،
  ثم شرائح المحادثات/المجموعات **لذلك اليوم فقط**، مع عدد سطور كل شيت.
- اليوم يُحسب بتوقيتك `APP_TZ` (افتراضي `Asia/Damascus`) — لا بتوقيت UTC.

### 3) مجموع اليوم وملخّص نهاية اليوم
- **مباشرة في الصفحة:** «مجموع السبت، ٢١ نوفمبر: N حركة» + مدين/دائن/صافي لكل عملة.
- **زر «إرسال ملخّص اليوم»** يرسل الملخّص إلى رقم/مجموعة الآن.
- **تلقائيًا:** يُرسل مرة واحدة كل يوم عند `DAILY_REPORT_AT` (افتراضي `23:50`)
  إلى `WA_DAILY_REPORT_TO` (أو `WA_AUTO_SUMMARY_TO`)، ويُسجَّل أنه أُرسل فلا يتكرر.

نموذج الرسالة:
```
📅 *ملخّص السبت، ٢١ نوفمبر* (2026-11-21)
• عدد الحركات: 7
• USD: مدين 500,000 · دائن 2,000 · الصافي 498,000
• EGP: مدين 2,750,000 · دائن 0 · الصافي 2,750,000

*حسب المحادثات والمجموعات:*
• أحمد الجندي: 2 حركة · صافي USD 498,000
• مجموعة مبيعات الفرع: 2 حركة · صافي EGP 2,750,000
```

| المسار | الوظيفة |
| --- | --- |
| `GET /api/sheet?day=today\|yesterday\|<تاريخ>\|all&sheet=<id>` | سطور يوم/شيت + مجموع اليوم لكل عملة |
| `GET /api/summary/daily?date=` | تقرير يوم كامل (لكل عملة ولكل شيت) |
| `POST /api/summary/daily/send {date?, to?}` | إرسال ملخّص اليوم (أو `preview:true` لعرض النص فقط) |

### المتغيّرات الجديدة
```env
APP_TZ=Asia/Damascus
DEFAULT_CURRENCY=USD
DAILY_REPORT_ENABLED=1
DAILY_REPORT_AT=23:50
WA_DAILY_REPORT_TO=9639xxxxxxxx   # أو JID مجموعة
```

## استكشاف الأخطاء

### زر الدخول يبقى على «جارٍ التحقق…»
حدث هذا عندما تُعرض المنصّة داخل **إطار مضمّن (iframe)** بلا `allow-same-origin` أو عند حظر الكوكيز:
طلب الدخول ينجح، لكن المتصفح لا يحفظ الكوكي، فيعيد `middleware` إلى `/login` ولا يكتمل التنقّل.

ما تغيّر لمعالجة ذلك:
1. **تحقّق بعد الدخول**: يُطلب `/api/auth/session`؛ إن لم تكن الجلسة قابلة للاستخدام تظهر رسالة واضحة بدل الدوران.
2. **شبكة أمان (12 ثانية)**: الزر يعود لحالته الطبيعية دائمًا.
3. **تنقّل كامل** (`window.location.assign`) بدل `router.push` لضمان قراءة الكوكي في أول طلب للخادم.
4. **كوكي متوافق مع الإطارات**: على https يُضبط `SameSite=None; Secure`، وعلى http `SameSite=Lax`.
5. **وضع المعاينة** `DEMO_MODE=1`: يتيح التصفّح دون جلسة (تظهر شارة «وضع المعاينة» في الشريط العلوي).
   ملف `.env.local` في هذه المساحة يفعّله. **في الإنتاج: احذفه أو اجعله `0`.**

### الدخول يعمل لكن الصفحات تعيدني إلى /login
تأكّد أن `amanah_session` يُحفظ فعلًا (DevTools → Application → Cookies)، وأن النطاق (Domain) والنطاق الفرعي متطابقان.
خلف بروكسي/CDN تأكّد من تمرير ترويسة `Host` و`X-Forwarded-Proto=https` حتى يُضبط الكوكي `Secure` بشكل صحيح.
